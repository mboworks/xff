      19              : // `--archive-mount`: give an archive member a real path by MOUNTING its container, rather than by
      20              : // copying the member out of it (`--archive-extract`, extract.h).
      21              : //
      22              : // Both answer the same question - "what path can a child process open for this member?" - and they
      23              : // differ in what the child then sees. An extracted member is a copy: a formatter edits the copy and
      24              : // reports success while the archive is untouched. A mounted member is the container itself, served
      25              : // read-only, so `{}` names a path INSIDE the archive and a tool that only reads (a compiler, a
      26              : // checksum, `grep`) needs no copy at all. Writes still cannot reach the container - the mount has
      27              : // no write callbacks - so mounting arms nothing extraction did not.
      28              : //
      29              : // One mount per CONTAINER (not per member), kept for the run: mounting is a kernel operation, and
      30              : // members of one archive are usually visited together.
      31              : //
      32              : // Mounting is a per-MACHINE capability: the fuse extra may not be linked, and even when it is, the
      33              : // machine may have no runtime fuse3 or no permission to mount. That is a DEGRADE, never a failure -
      34              : // `PathFor` returns nothing, the caller falls back to extraction, and `DegradeReason` carries the
      35              : // one-line explanation the run reports once.
