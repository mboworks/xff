      19              : // A read-only `vfs::FileSystem` over ONE archive container, so the whole expression grammar
      20              : // (`-name`, `-size`, `-type`, the printing actions) matches an archive's members at virtual paths
      21              : // like `foo.tgz!inner/x` - the spelling being whatever --archive-separator / --archive-prefix say
      22              : // (`member_path.h`).
      23              : //
      24              : // It implements the seam from @xff_extras_api, never the xff core, so the archive extra stays a
      25              : // standalone module the core knows nothing about.
      26              : //
      27              : // Three properties are decisions rather than implementation details:
      28              : //
      29              : //  * Every member is `read_only` with `source == kArchiveMember`. That is what makes `-delete` and
      30              : //    the exec family REFUSE members instead of silently skipping them.
      31              : //  * Implicit parent directories are SYNTHESIZED. Tar streams routinely store `a/b/c.txt` with no
      32              : //    entry for `a/` or `a/b/`, so a walk that trusted the stored list would find nothing to descend.
      33              : //  * The CONTAINER keeps its real-filesystem identity: this backend answers only for the container
      34              : //    path itself (as a directory, so a walk can enter it) and for member paths under it. The real
      35              : //    file stays a real file to the rest of xff, which is what "dual identity" means.
      36              : //
      37              : // `ReadContent` is deliberately unimplemented in this slice: the reader lists members but does not
      38              : // extract data yet, so content predicates (`-grep`, `-content`, `{hash}`) get a clear Unimplemented
      39              : // rather than silence or an empty string. The next slice adds member extraction.
